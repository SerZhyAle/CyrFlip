CyrFlip کوئی ذاتی معلومات جمع، محفوظ، درج یا منتقل نہیں کرتی۔ یہ پوری طرح آپ ہی کے آلے پر چلتی ہے۔ اس کے اپنے کوئی سرور نہیں، نہ ٹیلی میٹری، نہ تجزیات، نہ اشتہار، نہ کوئی نگرانی اور نہ صارف کے کھاتے۔ ڈویلپر کو آپ کے بارے میں یا ایپ کے آپ کے استعمال کے بارے میں کوئی معلومات نہیں پہنچتیں۔

صرف ایک ہی خصوصیت متن کہیں بھیجتی ہے، اور وہ طے شدہ طور پر بند ہے: اختیاری مترجم۔ جب آپ اسے چالو کرکے ترجمے کی شارٹ کٹ دباتے ہیں تو منتخب متن اُس Ollama سرور کے پتے پر بھیجا جاتا ہے جو CyrFlip میں مقرر ہے - طے شدہ طور پر http://localhost:11434، یعنی ایک پروگرام جو آپ ہی کے کمپیوٹر پر چل رہا ہے، چنانچہ متن آلے سے باہر نہیں جاتا۔ اگر آپ یہ پتہ بدل کر کسی دوسری مشین کا کر دیں تو متن وہیں جائے گا؛ اور CyrFlip یہ بات ترتیب کے ساتھ ہی لکھ دیتی ہے۔

ایپ کس چیز تک رسائی لیتی ہے، اور کیوں

  • کی بورڈ۔ CyrFlip صرف دو مقاصد کے لیے عالمی کی بورڈ ہُک نصب کرتی ہے: اپنی شارٹ کٹ پہچاننے کے لیے (طے شدہ Ctrl+Shift+F12) اور فعال کی بورڈ خاکے کا کوڈ پڑھنے کے لیے (Windows میں نصب کوئی بھی خاکہ) تاکہ سکرین پر نشان دکھا سکے۔ اس شارٹ کٹ کے علاوہ وہ اُن مجموعوں کو بھی دیکھتی ہے جو آپ حروف کی حالت کی درستی، کلپ بورڈ کے منتظم، اپنی خاکہ تبدیلی کی جدول کی ہر سطر، اپنی ترجمے کی جدول کی ہر سطر اور کسی بھی فوری اجرا کے منظرنامے کو تفویض کرتے ہیں۔ جب ترجمہ لکھا جا رہا ہو تو وہ Esc پر بھی نظر رکھتی ہے تاکہ یہ کلید اسے منسوخ کر سکے - یہ کلید بہرحال اُسی ایپ تک پہنچتی ہے جس میں آپ کام کر رہے ہیں۔ وہ آپ کی کلیدوں کو ریکارڈ، درج، محفوظ یا منتقل نہیں کرتی۔ یہ کی لاگر نہیں ہے۔
  • کلپ بورڈ۔ جب آپ شارٹ کٹ دباتے ہیں تو CyrFlip منتخب متن کو لمحہ بھر کے لیے پڑھتی ہے (ایک مصنوعی نقل کے ذریعے)، اسے ایک خاکے سے دوسرے میں بدلتی ہے، نتیجہ چسپاں کرتی ہے، پھر کلپ بورڈ کا پچھلا مواد بحال کر دیتی ہے۔ یہ سب مقامی طور پر اور صرف اُسی لمحے ہوتا ہے جب آپ خود کہیں۔ اس میں سے کچھ بھی کہیں نہیں بھیجا جاتا۔
  • کلپ بورڈ کی تاریخ (اختیاری)۔ طے شدہ طور پر بند۔ اگر آپ اسے چالو کریں تو CyrFlip پکڑا گیا یونیکوڈ متن مقامی طور پر محفوظ کرتی ہے۔ یہ تاریخ موجودہ Windows کھاتے کے لیے Windows DPAPI سے خفیہ کی جاتی ہے؛ آپ اسے کسی بھی وقت روک، خالی یا بند کر سکتے ہیں۔ CyrFlip اسے کبھی کہیں نہیں بھیجتی۔
  • فعال کھڑکی اور خاکہ۔ ایپ یہ پڑھتی ہے کہ کون سی کھڑکی مرکزِ توجہ میں ہے اور وہ کون سا کی بورڈ خاکہ استعمال کر رہی ہے، تاکہ نشان کو رکھ سکے اور تازہ کر سکے۔ یہ معلومات صرف یادداشت میں استعمال ہوتی ہیں، نہ محفوظ کی جاتی ہیں نہ منتقل۔ اگر آپ شارٹ کٹ ریموٹ ڈیسک ٹاپ کے حوالے کریں کو چالو کریں، اور صرف اُسی لمحے جب CyrFlip کی اپنی کوئی شارٹ کٹ واقعی دبائی جائے، تو وہ فعال کھڑکی کے قابلِ عمل فائل کا نام بھی پڑھتی ہے تاکہ ریموٹ ڈیسک ٹاپ کلائنٹ پہچان سکے۔
  • Windows کی اندراج ترتیبات۔ «Windows کی زبانیں» ٹیب آپ کی جانب سے خود Windows کی ترتیبات میں تبدیلی کرتا ہے: نصب شدہ کی بورڈ خاکے (HKCU\Keyboard Layout\Preload اور HKCU\Control Panel\International\User Profile)، زبان بدلنے کا چکری مجموعہ، اور فی زبان براہِ راست شارٹ کٹ (HKCU\Control Panel\Input Method\Hot Keys)۔ یہ نظام کی ترتیبات ہیں: یہ آپ کے آلے پر رہتی ہیں اور CyrFlip بند ہونے کے بعد بھی کام کرتی رہتی ہیں۔ اپنی پہلی تبدیلی سے پہلے CyrFlip پچھلی حالت کا ایک بار کا عکس اپنی رجسٹری کلید میں محفوظ کر لیتی ہے، تاکہ آپ اسے بحال کر سکیں۔
  • فوری اجرا (اختیاری)۔ منظرناموں کا لانچر طے شدہ طور پر بند ہے۔ چالو کرنے پر یہ وہی پروگرام، سکرپٹ اور yt-dlp ڈاؤن لوڈ چلاتا ہے جو آپ نے متعین کیے، اور صرف تب جب آپ کہیں: اطلاعاتی علاقے سے، ترتیبات کی جدول سے، آپ کی دی ہوئی شارٹ کٹ سے، یا ٹاسک بار کی جمپ لسٹ سے۔ منتظم کے اختیارات وہ صرف اُس منظرنامے کے لیے مانگتا ہے جسے آپ نے «بطور منتظم چلائیں» کا نشان دیا ہو، اور yt-dlp ڈاؤن لوڈ کے لیے لکھا ہوا ربط اُس ایک بار کے اجرا کے لیے اُس اوزار کے حوالے کیا جاتا ہے اور محفوظ نہیں ہوتا۔ ماڈیول چالو کرنے سے آپ کے منظرناموں کے نام ٹاسک بار کی جمپ لسٹ میں بھی شائع ہوتے ہیں، جسے Windows آپ ہی کے صارف پروفائل میں رکھتا ہے۔
  • مترجم (اختیاری)۔ طے شدہ طور پر بند؛ اور جب تک بند ہے، CyrFlip نیٹ ورک کا کوئی رابطہ سرے سے نہیں کھولتی۔ چالو ہونے پر، ترجمے کی شارٹ کٹ دبانے پر CyrFlip منتخب متن لیتی ہے (وہی مصنوعی نقل جو اوپر بیان ہوئی) اور اسے HTTP کے ذریعے اپنی ترتیبات میں درج Ollama کے پتے پر بھیجتی ہے - اگر آپ نے بدلا نہ ہو تو http://localhost:11434، یعنی آپ ہی کے کمپیوٹر پر ایک پروگرام۔ اطلاعاتی علاقے کا اندراج کلپ بورڈ کا ترجمہ کریں، جو صرف مترجم چالو ہونے پر دکھائی دیتا ہے، اُسی پتے پر منتخب متن کے بجائے کلپ بورڈ کا موجودہ مواد بھیجتا ہے۔ Ollama ایک الگ، مفت مصنوعہ ہے جسے آپ خود نصب کرتے ہیں؛ CyrFlip اسے ساتھ نہیں دیتی اور اس کا کوئی کھاتہ یا کلید نہیں۔ ترجمہ ایک کھڑکی میں دکھایا جاتا ہے اور - صرف اُس صورت میں جب آپ یہ اختیارات چالو کریں - کلپ بورڈ پر نقل ہوتا ہے (جہاں اختیاری تاریخ اسے ہر دوسری نقل کی طرح درج کرتی ہے) یا آپ کے منتخب متن پر چسپاں کر دیا جاتا ہے۔ CyrFlip کوئی ترجمہ محفوظ نہیں کرتی، ان کا کوئی ریکارڈ نہیں رکھتی اور ڈویلپر کو کچھ نہیں بھیجتی۔ پورٹیبل نسخے میں Ollama نصب کریں کا بٹن سرکاری نصب کنندہ ollama.com سے اتارتا ہے؛ Microsoft Store کا نسخہ صرف وہ ویب سائٹ کھولتا ہے۔ ماڈل کن زبانوں پر عبور رکھتا ہے، یہ سوال ماڈل سے ہے: CyrFlip تو بس اسے متن پہنچاتی ہے۔

مقامی فائلیں جو CyrFlip لکھتی ہے

  • خاکے کی فائل۔ CyrFlip موجودہ خاکے کا کوڈ - دو حرفی قدر جیسے EN، ZH، RU یا AR - ایک چھوٹی مقامی فائل میں لکھتی ہے (%LOCALAPPDATA%\CyrFlip\layout.txt، یا Microsoft Store کے نسخے میں %ProgramData%\CyrFlip\layout.txt)، تاکہ اختیاری VS Code توسیع مدوّن کے کرسر کے پاس نشان دکھا سکے۔ اس میں کوئی ذاتی معلومات نہیں ہوتیں اور یہ کبھی آپ کے آلے سے باہر نہیں جاتی۔
  • ترتیبات اور تاریخ۔ ترتیبات HKCU\Software\CyrFlip میں محفوظ ہوتی ہیں - بشمول آپ کی تبدیلی کی جدول اور اوپر بیان کردہ Windows اندراج ترتیبات کے ایک بار کے عکس۔ کلپ بورڈ کی تاریخ چالو ہو تو وہ ایپ کے ڈیٹا فولڈر میں DPAPI سے محفوظ صورت میں مقامی طور پر رکھی جاتی ہے۔ کوئی پرانی config.json منتقلی کے دوران ایک بار پڑھی جا سکتی ہے۔ ان میں سے کچھ بھی آپ کے آلے سے باہر نہیں جاتا۔
  • فوری اجرا کے منظرنامے۔ آپ کا بنایا ہوا ہر منظرنامہ اپنی الگ XML فائل کی صورت میں %APPDATA%\CyrFlip\Scenarios میں محفوظ ہوتا ہے اور اس میں بعینہٖ وہی ہوتا ہے جو آپ نے لکھا: نام، پروگرام یا سکرپٹ کا راستہ، اس کے دلائل اور کام کا فولڈر۔ یہ آپ کے آلے پر رہتے ہیں، آپ انہیں بدل یا حذف کر سکتے ہیں، اور ماڈیول بند کرنے پر بھی جوں کے توں رہتے ہیں۔ ماڈیول ایک مختصر سرگرمی لاگ بھی جوڑتا ہے (launcher.log، خاکے کی فائل کے پہلو میں) جس میں درج ہوتا ہے کہ کوئی منظرنامہ شروع ہوا اور کوئی کیوں ناکام ہوا - وہ yt-dlp کا ربط، کلپ بورڈ کا مواد یا کلیدوں کی ضربیں کبھی درج نہیں کرتا۔
  • تشخیصی رپورٹ۔ CyrFlip caret-diagnostics.txt کو خاکے کی فائل کے پہلو میں صرف تب لکھتی ہے جب آپ خود کرسر کی جگہ کی تشخیص کریں… چلائیں۔ اس میں درج ہوتا ہے کہ Windows اور UI آٹومیشن مرکزِ توجہ والے متن کے خانے کے بارے میں کیا بتاتے ہیں؛ یہ کہیں نہیں بھیجی جاتی، اور آپ اسے حذف کر سکتے ہیں۔
  • مصنف کے لیے لاگز کا آرکائیو۔ صرف جب آپ خود لاگز مصنف کو بھیجیں.. دباتے ہیں، CyrFlip اپنے تشخیصی لاگز اور ایک کنفیگریشن رپورٹ کو لے آؤٹ فائل کے ساتھ reports فولڈر میں ایک ZIP میں جمع کرتا ہے اور اُس منسلکہ کے ساتھ ڈیولپر کے لیے پیغام کھولتا ہے۔ کلپ بورڈ کی تاریخ اُس آرکائیو کا حصہ کبھی نہیں ہوتی۔ لاگز میں فائلوں کے راستے ہوتے ہیں اور اُن میں آپ کے Windows اکاؤنٹ کا نام؛ ونڈو یہ صاف کہتی ہے اور پیغام بننے سے پہلے آرکائیو کھولنے دیتی ہے۔ جب تک آپ اپنے میل پروگرام میں بھیجیں نہ دبائیں، کچھ نہیں بھیجا جاتا - CyrFlip کا اپنا کوئی بھیجنے کا راستہ نہیں۔

معلومات کا اشتراک

کوئی نہیں۔ CyrFlip نہ ڈویلپر کو اور نہ کسی تیسرے فریق کو کوئی معلومات دیتی ہے۔ جو واحد چیز کبھی بھیجی جاتی ہے وہ آپ کا منتخب کردہ متن ہے، اُسی مترجم کے پتے پر جو آپ نے خود چنا - طے شدہ طور پر آپ ہی کے کمپیوٹر کا ایک پروگرام - اور صرف اُس وقت تک جب یہ اختیاری خصوصیت چالو ہو۔ لاگز مصنف کو بھیجیں بٹن بھی مستثنیٰ نہیں: یہ آپ ہی کے میل پروگرام میں پیغام تیار کرتا ہے، آرکائیو آپ پہلے کھول سکتے ہیں، اور بھیج صرف آپ سکتے ہیں۔
