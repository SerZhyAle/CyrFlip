# Хоткеи переключения языка Windows — спецификация (идея, v0.1)

**Статус:** **реализовано** 2026-07-24 (`src/CyrFlip/LanguageHotkeys.cs` + вкладка «Языки Windows»
в `SettingsForm`). Проверки §8 выполнены частично — журнал в §9; две из четырёх остаются за
пользователем, потому что требуют перезахода в сеанс и установленной MSIX-сборки.

**Расширено 2026-07-25:** по запросу пользователя вкладка стала самодостаточной заменой раздела
«Язык и регион» Windows — добавлены **установка/удаление/порядок раскладок клавиатуры**
(`InputLayouts.cs`, `LayoutPickerDialog.cs`) и **редактируемый цикл переключения**
(`LanguageHotkeys.SetToggle`). Языковые пакеты (перевод самой Windows) сознательно вне области —
это загрузка из сети, остаётся за кнопкой «Открыть настройки Windows». Ключевой факт Win11:
раскладки хранятся одновременно в легаси `Keyboard Layout\Preload` и в авторитетном современном
`Control Panel\International\User Profile`; второе перезаписывает первое при входе в сеанс, поэтому
оба хранилища пишутся согласованно из одного канонического списка KLID. Полный цикл (добавить
украинскую → проверить оба хранилища и список → сделать по умолчанию → удалить → восстановить
байт-в-байт) проверен на живом реестре временным тестом.

**Дата:** 2026-07-24. **Автор запроса:** пользователь (SerZhyAle).

## 1. Идея в одной фразе

Добавить в CyrFlip слой настроек **«прямые хоткеи на язык»** — `Ctrl+1` → английский,
`Ctrl+2` → русский, `Ctrl+3` → украинский, — который CyrFlip **только задаёт и показывает**,
а обрабатывает их **сама Windows**.

**Ключевая граница ответственности:** это не третий хоткей CyrFlip. `KeyboardHook` эти комбинации
**не видит, не перехватывает и не глотает**. Мы выступаем редактором настроек операционной системы —
пишем в реестр Windows и просим ОС перечитать его. Если CyrFlip выгрузить, хоткеи продолжат работать.

**Зачем:** сценарий пользователя — макрос на боковой кнопке мыши шлёт `Ctrl+1` + пароль, и есть
гарантия, что пароль наберётся латиницей. Штатный UI Windows для этого спрятан глубоко
(Параметры → Время и язык → Ввод → Дополнительные параметры клавиатуры → Сочетания клавиш
для языков ввода → диалог из Windows XP) и умеет меньше, чем сам механизм (см. §3).

## 2. Как это устроено в Windows (проверено эмпирически)

Проверено дампом реестра на машине пользователя 2026-07-24.

### 2.1 Хранилище

```
HKEY_CURRENT_USER\Control Panel\Input Method\Hot Keys\<ID>
```

где `<ID>` — имя подраздела из 8 hex-цифр. Каждый подраздел содержит ровно три значения типа
`REG_BINARY` длиной 4 байта (little-endian DWORD):

| Значение | Смысл |
| --- | --- |
| `Key Modifiers` | битовая маска модификаторов |
| `Virtual Key` | VK-код клавиши-триггера |
| `Target IME` | HKL целевой раскладки (0 — если хоткей не привязан к раскладке) |

### 2.2 Диапазон ID для «переключиться на язык X»

`IME_HOTKEY_DSWITCH_FIRST = 0x00000100` … `IME_HOTKEY_DSWITCH_LAST = 0x0000011F` — 32 слота
«direct switch». Именно они нам нужны. Остальные наблюдавшиеся ID — штатные хоткеи IME, их
трогать нельзя:

```
00000010, 00000011, 00000012   — IME_CHOTKEY_*  (китайский)
00000070, 00000071, 00000072   — IME_THOTKEY_*  (переключение IME/не-IME)
00000200 … 00000203            — IME_JHOTKEY_*  (японский)
```

### 2.3 Живой пример с машины пользователя

```
--- 00000104
    Key Modifiers = 06 C0 00 00     → 0x0000C006
    Target IME    = 11 04 01 E0     → HKL 0xE0010411 (японский IME)
    Virtual Key   = 30 00 00 00     → 0x30 = '0'
```

Читается как: **Ctrl+Shift+0 → переключиться на японский IME**. Японского нет в
`HKCU\Keyboard Layout\Preload` (там только `1 = 00000419` русский, `2 = 00000409` английский),
то есть это **осиротевшая запись** из поставки Windows. Наш редактор должен такие показывать
и предлагать удалить (§5.4), а не молча затирать.

### 2.4 Кодировка `Key Modifiers`

Стандартные флаги `MOD_*`:

| Флаг | Значение |
| --- | --- |
| `MOD_ALT` | `0x0001` |
| `MOD_CONTROL` | `0x0002` |
| `MOD_SHIFT` | `0x0004` |
| `MOD_WIN` | `0x0008` |
| `MOD_IGNORE_ALL_MODIFIER` | `0x0400` |
| `MOD_ON_KEYUP` | `0x0800` |
| `MOD_RIGHT` | `0x4000` |
| `MOD_LEFT` | `0x8000` |

`0xC006` = `MOD_CONTROL | MOD_SHIFT | MOD_LEFT | MOD_RIGHT` — то есть «Ctrl+Shift, любой из парных
клавиш». Пара `MOD_LEFT|MOD_RIGHT` = «всё равно, левый или правый», и это то, что мы будем писать
по умолчанию. Штатный диалог Windows, напротив, для варианта «Left Alt+Shift» пишет только
`MOD_LEFT`.

### 2.5 Кодировка `Target IME`

HKL как DWORD: младшее слово — LANGID, старшее — идентификатор раскладки.
Для обычных (не-IME) раскладок старшее слово равно младшему:

| Язык | HKL |
| --- | --- |
| English (US) | `0x04090409` |
| Русская | `0x04190419` |
| Українська | `0x04220422` |

Значение брать **не константой**, а из `GetKeyboardLayoutList` — у пользователя может стоять
вариант раскладки (например, «Русская — машинопись»), и тогда старшее слово другое.

### 2.6 Общий переключатель (для справки в UI)

```
HKEY_CURRENT_USER\Keyboard Layout\Toggle
    Hotkey / Language Hotkey / Layout Hotkey  (REG_SZ)
```

На машине пользователя: `Hotkey = "1"`. Известное соответствие: `1` = Left Alt+Shift,
`2` = Ctrl+Shift, `4` = Grave Accent (`` ` ``). Значение `3` предположительно «не назначено» —
**точный смысл `3` не подтверждён, проверить перед показом в UI** (§8.3). Этот раздел мы
**только читаем и показываем**; редактирование цикла переключения — вне области v0.1.

## 3. Важное уточнение по «Ctrl+1»

Штатный диалог Windows предлагает для каждого языка только два шаблона —
**Ctrl+Shift+цифра** и **Left Alt+Shift+цифра** (цифра 0–9). Чистого `Ctrl+1` в списке нет.

Но формат хранения (§2.1) хранит произвольную маску модификаторов и произвольный VK. То есть
`Ctrl+1` записывается как `Key Modifiers = 0x0000C002`, `Virtual Key = 0x31` — и это,
по формату, полностью законная запись.

**Отсюда два следствия:**

1. Это и есть главная добавленная ценность фичи: CyrFlip сможет назначить комбинации, которых
   штатный UI не предлагает. Не «удобная обёртка над тем же самым», а строго больше.
2. **Работает ли Windows с такой маской фактически** — не проверено. Возможно, движок IMM
   принимает любую маску; возможно, он ограничивает direct-switch хоткеи известными шаблонами.
   Это **блокирующая проверка №1** (§8.1). Если произвольные маски не поддерживаются,
   фича деградирует до «удобный редактор Ctrl+Shift+N / LeftAlt+Shift+N» — всё ещё полезно,
   но обещать `Ctrl+1` в этом случае нельзя, и формулировки в UI и в описании релиза
   надо будет поменять.

## 4. Применение изменений

После записи в реестр вызвать:

```csharp
SystemParametersInfo(SPI_SETLANGTOGGLE /* 0x005B */, 0, IntPtr.Zero, 0);
```

Документация SPI_SETLANGTOGGLE: «задаёт набор горячих клавиш для переключения языков ввода…
**перечитывая реестр**». `uiParam`/`pvParam` не используются.

**Не проверено:** покрывает ли `SPI_SETLANGTOGGLE` раздел `Input Method\Hot Keys`, или он
перечитывает только `Keyboard Layout\Toggle`. Если только Toggle — потребуется выход из сеанса
и повторный вход. Это **блокирующая проверка №2** (§8.2). Если перечитывания не происходит,
UI обязан честно писать «изменения вступят в силу после перезахода в Windows», а не делать вид,
что применилось.

## 5. Пользовательский интерфейс

### 5.1 Где

Новая вкладка **«Языки»** в `SettingsForm` (сейчас там: Общие, Индикаторы, Горячие клавиши,
Буфер обмена, О программе). Отдельная вкладка, а не строки внутри «Горячих клавиш», —
потому что семантика принципиально другая: это настройки Windows, а не CyrFlip, и смешивать
их в одном списке значит вводить пользователя в заблуждение насчёт того, кто что обрабатывает.

### 5.2 Шапка вкладки

Текст-пояснение в стиле остальных вкладок:

> Эти сочетания обрабатывает сама Windows, а не CyrFlip. Они продолжат работать, даже если
> CyrFlip закрыт. CyrFlip только записывает их в настройки системы и показывает текущее состояние.

### 5.3 Таблица установленных раскладок

Строка на каждый HKL из `GetKeyboardLayoutList`:

| Язык | Раскладка | HKL | Сочетание | |
| --- | --- | --- | --- | --- |
| English (United States) | US | `04090409` | Ctrl+1 | [Задать] [Очистить] |
| Русский | Russian | `04190419` | Ctrl+2 | [Задать] [Очистить] |
| Українська | Ukrainian | `04220422` | Ctrl+3 | [Задать] [Очистить] |

«Задать» открывает `HotkeyDialog` (переиспользуем существующий, с заголовком «Сочетание для
переключения на <язык>»). Потребуется послабление: текущий `HotkeyDialog` требует минимум один
модификатор Ctrl/Shift/Alt — для этой задачи требование сохраняем (голая цифра как глобальный
хоткей — плохая идея), но снимаем ограничение на набор триггеров, если проверка §8.1 покажет,
что ОС принимает произвольные VK.

### 5.4 Осиротевшие записи

Отдельным блоком под таблицей, свёрнутым по умолчанию: записи из диапазона `0x100…0x11F`,
чей `Target IME` не соответствует ни одной установленной раскладке (как `00000104` → японский
в §2.3). Показываем «Ctrl+Shift+0 → раскладка 0xE0010411 (не установлена)» и кнопку «Удалить».
Ничего не удаляем сами.

### 5.5 Только чтение

Строкой внизу: текущее значение цикла переключения (§2.6) — «Переключение по кругу:
Left Alt+Shift» — и кнопка **«Открыть настройки Windows»** (`ms-settings:keyboard`) для всего,
что мы не редактируем.

### 5.6 Резервная копия и откат

Перед первой записью сохранить исходное состояние всего диапазона `0x100…0x11F` в
`HKCU\Software\CyrFlip\LanguageHotkeysBackup` (одна строка JSON). Кнопка
**«Вернуть как было до CyrFlip»** восстанавливает. Мы правим общесистемные настройки
пользователя — путь назад обязателен.

## 6. Код

### 6.1 Новый модуль `src/CyrFlip/LanguageHotkeys.cs`

Один класс, одна ответственность (как принято в проекте). Без состояния — источник истины
реестр Windows, своей копии настроек мы **не заводим**, чтобы не было рассинхронизации, когда
пользователь поменяет что-то штатным диалогом.

```csharp
internal static class LanguageHotkeys
{
    // Одна назначенная запись direct-switch.
    internal sealed class Entry
    {
        public int    Id        { get; set; }  // 0x100..0x11F
        public IntPtr TargetHkl { get; set; }
        public uint   Modifiers { get; set; }
        public uint   VirtualKey{ get; set; }
        public string Display   { get; set; }  // "Ctrl+1"
    }

    public static List<Entry> ReadAll();                      // весь диапазон 0x100..0x11F
    public static void Assign(IntPtr hkl, string hotkey);     // занять/переиспользовать слот
    public static void Clear(IntPtr hkl);                     // удалить подраздел
    public static void Remove(int id);                        // удалить осиротевшую запись
    public static void ApplyToWindows();                      // SPI_SETLANGTOGGLE
    public static string BackupAll();                         // JSON снимок
    public static void RestoreAll(string json);
}
```

Разбор/сборка строки вида `"Ctrl+1"` — переиспользовать `Hotkey.cs` (там уже есть парсер
модификаторов + VK и `Display`), добавив конвертацию `Hotkey` → маска `MOD_*` и обратно.
Дублировать таблицу клавиш вторым списком нельзя — она уже одна, пусть такой и остаётся.

**Выбор слота в `Assign`:** если для этого HKL запись уже есть — переписать её ID.
Иначе занять наименьший свободный ID в `0x100…0x11F`. Не занимать ID, уже занятый чужой
записью, даже осиротевшей.

**Проверка конфликтов** перед записью, в двух направлениях:
1. с хоткеями самого CyrFlip (`Hotkey.SameChord` против flip / case-flip / history) — иначе
   `KeyboardHook` проглотит клавишу и до Windows она не дойдёт;
2. с уже назначенными языковыми хоткеями.

При конфликте — отказ с внятным сообщением, а не тихая перезапись.

### 6.2 Правки в существующих файлах

- `WindowInterop.cs` — `SystemParametersInfo` (если ещё нет) + константа `SPI_SETLANGTOGGLE`,
  флаги `MOD_*`, `GetKeyboardLayoutList` уже есть.
- `SettingsForm.cs` — вкладка «Языки» (§5), иконка в `tabIcons`.
- `HotkeyDialog.cs` — необязательный параметр «разрешённые триггеры» (по результату §8.1).

- `docs/` — раздел в трёх языках; `msix/store-listing-export.csv` — строка в «Что нового».

Локализация: строки вкладки во все три языка UI (EN/RU/UK), как в остальном UI.

## 7. Риск: виртуализация реестра в MSIX-сборке

**Это самый серьёзный риск фичи, и он специфичен для магазинной сборки.**

Пакеты MSIX по умолчанию виртуализируют запись в `HKCU`: запись уходит в приватный куст пакета,
а не в реальный реестр пользователя. Если это так, то в Store-версии CyrFlip запись в
`HKCU\Control Panel\Input Method\Hot Keys` **окажется невидимой для Windows**, и фича молча
не будет работать — при том что портативная ZIP-версия будет работать нормально.

Отключается это через `<desktop6:RegistryWriteVirtualization>disabled</...>` в манифесте пакета,
что требует ограниченной возможности `unvirtualizedResources` и, вероятно, обоснования при
сертификации в Store.

**Обязательно проверить до реализации** (§8.4). Возможные исходы:
- виртуализации нет / отключается без проблем → делаем как описано;
- отключить нельзя → в MSIX-сборке вкладка «Языки» показывается в режиме «только чтение»
  с пояснением и кнопкой «Открыть настройки Windows». `PackageInfo.cs` уже умеет отличать
  MSIX-запуск, так что развилка дешёвая.

Молча деградировать нельзя ни в каком случае: пользователь должен видеть, почему не применилось.

## 8. Что проверить до реализации (блокирующие проверки)

Порядок важен: 8.1 и 8.4 определяют, существует ли фича в заявленном виде.

**8.1 — Принимает ли Windows произвольную маску модификаторов.**
Вручную создать `HKCU\Control Panel\Input Method\Hot Keys\00000100` с
`Key Modifiers = 02 C0 00 00` (`0xC002`, Ctrl без Shift), `Virtual Key = 31 00 00 00` (`'1'`),
`Target IME = 09 04 09 04` (`0x04090409`). Перезайти в сеанс, нажать `Ctrl+1` в Блокноте,
посмотреть на индикатор раскладки. Определяет §3.

**8.2 — Достаточно ли `SPI_SETLANGTOGGLE`.**
После записи вызвать `SystemParametersInfo(0x005B, 0, IntPtr.Zero, 0)` и проверить хоткей
**без** перезахода. Определяет формулировку в UI (§4).

**8.3 — Смысл значения `3` в `Keyboard Layout\Toggle`.**
Пройти штатный диалог по всем вариантам и снять дамп после каждого. Некритично — влияет
только на текст в §5.5.

**8.4 — Виртуализация реестра в MSIX.**
Собрать `msix/build-msix.ps1`, установить локально, из-под пакета записать пробное значение
в `HKCU\Control Panel\Input Method\Hot Keys\0000011F` и проверить `reg query` снаружи пакета.
Определяет §7.

Результаты проверок дописать сюда же, в §9, с датой — как это сделано в CLAUDE.md для
пути каретки в VS Code.

`Assign(EN, Ctrl+Shift+F9)` создаёт подраздел с `Key Modifiers = 06 C0 00 00` (`0xC006`),

штатный осиротевший `00000104`). Тест был временным и удалён — постоянные тесты покрывают
чистую часть (кодирование маски, выбор слота, именование VK).

**2026-07-24 — §8.1 (произвольная маска) НЕ проверена.** Записать `Ctrl+1` мы умеем и проверили,
что запись ложится в правильном формате. Отработает ли её движок IMM — покажет только нажатие
клавиши после перезахода в сеанс. До этой проверки нельзя утверждать, что `Ctrl+1` работает;
UI обещает ровно то, что сделано: «сочетание записано в настройки Windows».

**2026-07-24 — §8.2 (достаточно ли `SPI_SETLANGTOGGLE`) НЕ проверена.** Вызов делается после

**2026-07-24 — §8.3 (смысл кода `3` в `Keyboard Layout\Toggle`) НЕ проверена.** В UI цикл
переключения показывается вместе с числовым кодом (`Left Alt+Shift (1)`), чтобы неверная
подпись оставалась отслеживаемой.

**2026-07-24 — §8.4 (виртуализация реестра в MSIX) НЕ проверена.** Требует установленной
магазинной сборки. В UI под `PackageInfo.IsPackaged` показывается предупреждение о том, что
запись может уйти в контейнер пакета, и кнопка «Открыть настройки Windows» как обходной путь.
Функциональность не блокируется: заблокировать возможно работающий путь хуже, чем предупредить.

## 10. Область v0.1 — что НЕ входит

- Редактирование цикла переключения (`Keyboard Layout\Toggle`) — только чтение.
- Установка/удаление самих раскладок Windows — это `ms-settings:keyboard`.
- Хоткеи IME вне диапазона direct-switch (`0x10`, `0x70`, `0x200`…) — не трогаем.
- Перехват языковых хоткеев силами `KeyboardHook` — принципиально нет, это ломает всю идею
  фичи (см. §1) и вернёт зависимость от запущенного CyrFlip.
- Синхронизация между машинами.
