# Спецификация-идея v0.2
## Tray Clipboard History для CyrFlip

> Концепт дополнительной функции для текущего tray-приложения `CyrFlip`.
> Статус: идея / product-spec, не утверждённая к реализации.
>
> **v0.2 (2026-07-17):** уточнён UI окна (узкая вертикальная полоска, ячейки-зебра,
> визуальный якорь из первых 10 символов, кнопки закрепить/удалить на самой ячейке,
> запоминание позиции), и **история теперь сохраняется между запусками** (было: только в памяти).

---

## 1. Идея

Добавить в `CyrFlip` компактный **менеджер истории буфера обмена**, который:

- живёт внутри уже существующего tray-приложения;
- включается и выключается из трея;
- показывает **плавающее окно** с историей последних копирований;
- позволяет **мышкой выбрать** любой элемент истории и сделать его текущим содержимым буфера;
- не заменяет системную историю Windows, а **работает рядом** и ей не мешает.

Ключевая идея UX: это не отдельный тяжёлый clipboard manager, а **маленькое всегда-доступное окно-история**, которое можно держать под рукой рядом с рабочей зоной.

---

## 2. Пользовательский сценарий

Пользователь копирует несколько фрагментов текста в течение дня. Вместо `Win+V` и лишних нажатий он:

1. открывает окно истории из трея или по горячей клавише;
2. видит последние записи списком;
3. кликает мышкой по нужному фрагменту;
4. этот фрагмент становится активным в системном clipboard;
5. пользователь вставляет его обычным `Ctrl+V` в нужное приложение.

Окно может:

- оставаться поверх других окон;
- перетаскиваться мышкой;
- сворачиваться обратно в трей;
- быстро показываться и скрываться по комбинации клавиш.

---

## 3. Основные требования

### 3.1 Формат данных

Храним только:

- `Unicode text`
- `Rich Text Format (RTF)`

Не храним:

- изображения
- файлы
- HTML как отдельную сущность MVP
- бинарные/кастомные clipboard-форматы

Если в clipboard нет текста или RTF, запись просто игнорируется.

### 3.2 Что видно в истории

Для каждой записи показывать:

- краткий предпросмотр текста;
- время копирования;
- тип содержимого: `Text` или `RTF`;
- имя приложения-источника, **если удаётся определить**.

Пример строки:

- `22:14  Notepad  |  "пример текста..."`
- `22:15  Word     |  "заголовок отчёта..."`

### 3.3 Поведение окна

Окно истории - **узкая вертикальная полоска** с шапкой сверху и вертикальным списком ячеек под ней (подробный вид - §4). Оно:

- без тяжёлого main window;
- открывается из иконки в трее и по горячей клавише; **повторная горячая клавиша прячет (закрывает) окно**;
- **всегда `topmost` (поверх всех окон)** - это окно-«под рукой», оно не должно теряться за другими;
- **шапка** содержит имя (`Менеджер буфера`), кнопку-**лупу** поиска по истории (*реализуется на Этапе 2*, §4.6) и кнопку в правом углу, которая выглядит как **свернуть** (не крестик), потому что она **не закрывает приложение, а только прячет это окно** обратно в трей;
- скрывается (не завершает приложение) по `Esc`, кнопке в шапке или повторной горячей клавише;
- за **шапку** перетаскивается мышкой;
- **изменяется в размере пользователем по обеим осям**:
  - по **высоте**: минимум **3 ячейки**, максимум - сколько позволяет высота монитора;
  - по **ширине**: по умолчанию **узкое**, можно сузить до **~100 px** или расширить сколько угодно; при большей ширине под текст в ячейках становится больше места (§4.1);
- **запоминает последнюю позицию и размер (ширину и высоту)** и восстанавливает их при следующем показе;
- если запомненный монитор больше не подключён (или это первый запуск) - показывается **рядом с треем** с размерами по умолчанию.

### 3.4 Активация элемента

Взаимодействие с ячейкой:

- **левый клик по ячейке** - делает её содержимое текущим системным clipboard;
- **правый клик по ячейке** - закрепить/открепить её (перемещает в начало списка, см. §4.3);
- по желанию (настройка) окно скрывается после выбора;
- **не вставляет текст автоматически**;
- **не перехватывает `Ctrl+V`** и не ломает стандартное поведение Windows.

Дополнительно на самой ячейке есть маленькие кнопки-символы (§4.2) для закрепить/открепить и удалить.

### 3.5 Интеграция с треем

В tray-меню добавить, например:

- `Clipboard history`
- `Show history`
- `Always on top`
- `Start with Windows`
- `Clear history`
- `Pause history capture`

## 4. UX-детали

### 4.1 Вид окна и списка

Окно - узкая вертикальная полоска:

```
┌──────────────────────────────┐
│ Менеджер буфера      [🔍] [_] │  ← шапка: имя + лупа (Этап 2) + «свернуть» (прячет окно)
├──────────────────────────────┤
│ Приве́т, ми́р          📌  │
│ полный текст ячейки мелким    │  ← ячейка 1 (светлая полоса зебры)
│ шрифтом, до 3 строк, …     ✕ │
├──────────────────────────────┤
│ SELECT * FR            📌  │
│ ...остальной текст запроса    │  ← ячейка 2 (тёмная полоса зебры)
│ мелким шрифтом …           ✕ │
├──────────────────────────────┤
│ ...                           │
└──────────────────────────────┘
```

Список:

- **вертикальный**, свежие сверху; закреплённые (§4.3) - выше свежих;
- по умолчанию видно **последние 5 ячеек**; при растягивании окна по высоте - больше (минимум 3, максимум - высота монитора);
- **ширина** окна регулируется (§3.3): чем шире окно, тем больше места под текст в ячейках (длиннее строки до обрезки многоточием); при узком (до ~100 px) видно якорь и обрезанное превью;
- ячейки **равной высоты**;
- каждая ячейка - до **3 текстовых строк** превью:
  - **первые ~10 символов - крупным шрифтом** как визуальный якорь («что здесь лежит»),
  - остальной текст - **мелким шрифтом**;
  - длинный текст обрезается многоточием;
- ячейки подсвечены **зеброй** (чередование светлой/тёмной полосы), чтобы были видны границы;
- **тема (светлая/тёмная) наследуется от ОС**;
- активный hover подсвечивается.

### 4.2 Кнопки на ячейке

На каждой ячейке - две маленькие кнопки-символа у правого края:

- **правый верхний угол** - **закрепить/открепить** (значок булавки; закреплённая ячейка помечена и держится вверху списка);
- **правый нижний угол** - **удалить/очистить** эту запись (значок крестика).

Значки рисуются **монохромными GDI-глифами** (не emoji), цвет наследуется от темы ОС - чёткие на любом DPI, единый стиль с owner-drawn окном.

Клик по этим кнопкам действует только на свою ячейку и не трогает системный clipboard. (Дублирующий способ закрепить/открепить - правый клик по ячейке, §3.4.)

### 4.3 Закрепление

- закреплённая ячейка **перемещается в начало списка** и не вытесняется лимитом истории;
- открепление возвращает её в обычный поток по времени;
- закреплённые ячейки визуально помечены (значок `📌`).

### 4.4 Размер истории

**Обновлено в v0.2 (решение пользователя):** в MVP **храним всё** - жёсткого лимита количества нет. История - append-only лог, который может разрастаться (модель хранения - §7.2). Чистка/усечение - явные действия пользователя:

- `Очистить историю` и `Обрезать историю до 100` живут в **окне настроек** (см. [SettingsWindow_Spec_Idea_v0.1.md](SettingsWindow_Spec_Idea_v0.1.md), раздел Clipboard), а не автоматически;
- в окне-полоске подгружаем и рисуем только **последние N** записей (сколько влезает на экран), а не всю историю.

Лимит размера **одного элемента**: **128 KB** текста. Запись больше порога **не сохраняется вовсе** (не обрезается - чтобы возврат в буфер всегда был полным), и показывается **короткий тост**: «Фрагмент слишком большой для истории (>128 KB)». Это защищает от гигантских вставок.

### 4.5 Горячая клавиша

Отдельная горячая клавиша:

- показать/скрыть окно истории;
- **по умолчанию `Ctrl+Shift+F10`** (держится семейства F-клавиш рядом с flip `F12` и case `F11`, не конфликтует с браузером/системой);
- настраивается так же, как остальные хоткеи приложения (и проверяется на `SameChord` против flip/case-хоткеев).

### 4.6 Поиск по истории (Этап 2)

Кнопка-**лупа** в шапке (§3.3) открывает строку поиска/фильтра по истории. Реализуется на **Этапе 2**. Поскольку каждая запись несёт `Uuid` = хеш содержимого (§7.1), поиск идёт по тексту превью, а дедуп/сортировка - по `Uuid`.

## 5. Источник данных и ограничения Windows

### 5.1 Как отслеживать clipboard

Для Windows-реализации логичный путь:

- слушать изменения буфера через `AddClipboardFormatListener`;
- на каждое изменение читать `CF_UNICODETEXT`;
- отдельно проверять наличие `RTF` через зарегистрированный формат `Rich Text Format`;
- сохранять снимок данных в свою внутреннюю историю.

Это означает:

- системный clipboard остаётся системным;
- `CyrFlip` только подписывается на события и делает локальную копию текстовых данных;
- Windows Clipboard History (`Win+V`) продолжает работать как обычно.

### 5.2 Как определить приложение-источник

Если реализуемо, при захвате записи попытаться сохранить:

- `GetForegroundWindow()`;
- `GetWindowThreadProcessId()`;
- имя процесса;
- по возможности заголовок окна.

Ограничения:

- не всегда окно на переднем плане гарантированно является реальным источником copy;
- в некоторых приложениях источник будет определяться неточно;
- поэтому поле приложения должно считаться **best effort**, а не строгой гарантией.

### 5.3 Сосуществование с Windows Clipboard History

Требование: **не мешать штатному менеджеру буфера Windows**.

Для этого:

- не отключать системные механизмы;
- не чистить clipboard без явного действия пользователя;
- не подменять `Win+V`;
- не удалять форматы, которые приложению не принадлежат;
- при выборе старого элемента просто заново публиковать в clipboard текст/RTF.

Итог: Windows видит обычное обновление clipboard, как если бы пользователь снова скопировал этот текст.

## 6. Архитектура в рамках текущего проекта

Функция хорошо ложится в нынешнюю модель `CyrFlip`, потому что приложение уже:

- живёт в трее;
- не требует большого основного окна;
- работает как фоновый desktop helper;
- уже взаимодействует с clipboard.

### 6.1 Возможные новые компоненты

- `ClipboardHistoryService.cs`
  - подписка на события clipboard;
  - чтение `text/rtf`;
  - дедупликация;
  - лимит размера и количества элементов.

- `ClipboardHistoryEntry.cs`
  - модель записи истории:
  - `Uuid` - **хеш содержимого** (например SHA-256 от нормализованного текста); первичный ключ для дедупа/сортировки/поиска (§7.1)
  - `CreatedAt`
  - `PlainText`
  - `Rtf`
  - `SourceProcessName`
  - `SourceWindowTitle`
  - `IsPinned` (закреплённая держится вверху и не вытесняется лимитом)

- `ClipboardHistoryWindow.cs`
  - плавающее окно-полоска со списком ячеек (owner-drawn: якорь крупным + превью мелким, зебра, тема ОС);
  - шапка с именем и кнопкой «свернуть» (прячет окно, не завершает app);
  - левый клик по ячейке - вернуть в clipboard; правый клик - закрепить/открепить;
  - кнопки на ячейке: закрепить/открепить (верх-право), удалить (низ-право);
  - всегда topmost (поверх всех окон);
  - drag за шапку; resize по обеим осям (высота: мин. 3 ячейки, макс. высота монитора; ширина: мин. ~100 px, макс. без ограничения);
  - запоминание позиции/размера (ширины и высоты); fallback к области возле трея, если монитор пропал;
  - скрытие без завершения приложения (Esc / кнопка / повторный хоткей).

- обновления в `CyrFlipContext.cs`
  - новые пункты tray-меню;
  - hotkey показа/скрытия окна;
  - lifecycle запуска/остановки history service.

### 6.2 Связь с текущим ClipboardHandler

Текущий `ClipboardHandler` уже умеет аккуратно работать с clipboard во время flip-операций.
Для новой функции важно:

- не ломать существующий pipeline `copy -> transform -> paste`;
- помечать внутренние служебные clipboard-операции, чтобы история не засорялась собственными техническими копиями;
- отдельно решить, нужно ли сохранять в историю результат flip-операции пользователя.

Рекомендуемое поведение MVP:

- обычные пользовательские copy-события сохранять;
- внутренние временные clipboard-подмены во время flip не сохранять;
- итоговый осознанный результат flip можно сохранять как новый элемент истории.

## 7. Поведение данных

### 7.1 Дедупликация (по UUID, решение пользователя)

Каждая запись несёт `Uuid` = **хеш её содержимого**. Это делает дедуп, сортировку и поиск дешёвыми - сравниваем не тексты, а короткие ключи.

Поведение при копировании:

- считаем `Uuid` нового текста;
- ищем такой же `Uuid` **среди последних `1000` записей** (не по всей истории - иначе поиск дорожает с ростом лога);
- **если найден - «поднимаем наверх»**: запись становится верхней и обновляется `CreatedAt` (в append-логе это новая запись-touch с тем же `Uuid`, при отображении берётся самое свежее вхождение);
- если не найден - добавляем как новую запись.

Окно последних 1000 - компромисс: очень старый идентичный текст заведёт второе вхождение, но поиск дубля остаётся быстрым независимо от размера истории.

### 7.2 Хранение (append-only лог + DPAPI, решение пользователя)

**Обновлено в v0.2:** история **сохраняется между запусками**, храним **всё**, поэтому файл может разрастаться - модель оптимизирована под «быстро дописать в конец, прочитать последние N».

Модель:

- **append-only лог**: каждое событие - новая строка/запись в конец файла (`clipboard-history.log`), без переписывания всего файла;
- типы записей: `add` (новый текст), `touch` (подъём дубля наверх, §7.1), `pin`/`unpin`, `delete` (тумбстоун);
- каждая запись несёт `Uuid`, `CreatedAt`, метаданные (источник, `IsPinned`); полезная нагрузка (текст, позже RTF) - **зашифрована DPAPI** под учётной записью пользователя (`ProtectedData`, scope=CurrentUser), т.к. на диске лежат пароли/личное (§7.3);
- **чтение**: с конца файла назад собираем последние N уникальных по `Uuid` записей (сколько влезает на экран + запас), учитывая тумбстоуны/pin - **не читая весь лог**;
- **дедуп-окно**: последние `1000` записей (§7.1);
- расположение - MSIX-aware папка рядом с `layout.txt` (тот же выбор папки, что у логов);
- при старте файл читается с конца; отсутствующий/повреждённый файл = пустая история (не падать), битые записи пропускаются.

**Компакция.** Т.к. append-only лог со временем накапливает `touch`/`delete`, периодически (при старте или по действию из настроек) переписываем его начисто, оставляя только актуальное состояние. Операции `Очистить историю` и `Обрезать до 100` из окна настроек (§4.4) - это тоже компакция.

Позицию/размер окна и запомненный монитор (§3.3) храним отдельно - в реестре `HKCU\Software\CyrFlip` рядом с остальным конфигом, не в логе.

### 7.3 Приватность

Это чувствительная функция. Clipboard history почти всегда содержит:

- пароли
- ссылки
- письма
- фрагменты документов
- личные данные

Так как в v0.2 история **пишется на диск**, приватность важнее прежнего:

- вся фича **выключена по умолчанию** (opt-in) и помечена как экспериментальная;
- **файл истории зашифрован DPAPI** (scope=CurrentUser) уже в MVP - другой пользователь/другой ПК его не прочитает (§7.2);
- хранение **только локально**, без сети и телеметрии;
- **`Pause history capture`** - временно не захватывать (для ввода паролей и т.п.);
- понятная кнопка **`Clear history`** (стирает и память, и файл на диске);
- пер-ячейка **удаление** (§4.2) - убрать конкретную запись (тумбстоун + компакция);
- *(опция на будущее)* тумблер «не сохранять на диск / только в память» для тех, кому персист не нужен.

## 8. MVP и этапы

### MVP

Сделать минимально полезную версию:

1. Tray toggle для включения истории (по умолчанию выключено).
2. Отслеживание clipboard через listener + фильтрация собственных flip-операций (ловим только пользовательские копии).
3. Сохранение только `plain text`; запись >128 KB не сохраняется + короткий тост (§4.4).
4. Окно-полоска: ячейки-зебра, якорь крупным + превью мелким, тема ОС, монохромные GDI-глифы кнопок.
5. Левый клик по ячейке возвращает её в системный clipboard; **окно остаётся открытым**.
6. Закрепить/открепить (правый клик + кнопка на ячейке) и удалить (кнопка на ячейке).
7. Дедуп по `Uuid` (хеш содержимого) в последних 1000 с подъёмом дубля наверх (§7.1).
8. Окно всегда topmost; resize по обеим осям (высота: мин. 3 ячейки; ширина: мин. ~100 px, макс. без ограничения) + drag за шапку + запоминание позиции/размера; fallback к трею, если монитор пропал.
9. Горячая клавиша показать/скрыть окно (`Ctrl+Shift+F10` по умолчанию); повторный хоткей прячет окно.
10. Персист между запусками: **append-only лог, зашифрованный DPAPI**, чтение последних N; `Clear history` и `Pause capture` из трея.

Кнопка-лупа в шапке присутствует, но её функция (поиск) - Этап 2.

### Этап 2

- добавить `RTF`;
- показать приложение-источник в ячейке;
- **поиск/фильтр по истории** (кнопка-лупа в шапке, §4.6);
- *(опционально)* тумблер отключить «поверх всех» (по умолчанию окно всегда topmost);
- операции истории в окне настроек: `Очистить историю`, `Обрезать до 100` (§4.4).

### Этап 3

- отдельный режим ещё более компактного окна;
- экспорт/импорт истории;
- тумблер «только в память, без диска».

## 9. Негативные сценарии и ограничения

- Некоторые приложения публикуют clipboard в нестандартном виде, и текст может быть недоступен сразу.
- RTF может быть очень большим и замедлять UI, если не ограничить размер.
- Если окно истории всегда сверху, оно может мешать в маленьких рабочих областях.
- Источник копирования не всегда определится корректно.
- Случайный клик по старой записи меняет текущий clipboard, поэтому нужен аккуратный UX.
- Функция частично пересекается с `Win+V`, значит её ценность должна быть именно в постоянном окне и работе мышью.

---

## 10. Почему эта идея может подойти именно CyrFlip

Потому что `CyrFlip` уже:

- маленький;
- tray-first;
- текстоцентричный;
- работает как утилита быстрого доступа;
- уже имеет аккуратный код для clipboard-операций.

Функция расширяет сценарий "работы с текстом" без смены класса продукта:

- сейчас `CyrFlip` помогает исправить текст;
- clipboard history помогал бы быстро **повторно использовать** текст.

## 11. Рекомендация по позиционированию

Если идти в реализацию, лучше подавать это не как "ещё один универсальный clipboard manager", а как:

**"Лёгкая текстовая история буфера в трее, всегда под рукой, без конфликта с Win+V."**

Это удерживает фокус:

- только текст и RTF;
- только быстрый выбор;
- только компактный UI;
- без попытки конкурировать с большими многоформатными clipboard-комбайнами.

## 12. Итог

Идея реалистична для текущей архитектуры `CyrFlip`, особенно как отдельный опциональный модуль.
Самая сильная часть концепции - **постоянно доступное перетаскиваемое окно истории**, которое удобно выбирать мышкой.

Самые важные риски:

- **приватность** (в v0.2 усилилась - история пишется на диск; отсюда opt-in, `Pause`, `Clear`, пер-ячейка удаление, на будущее - DPAPI);
- пересечение со штатным `Win+V` (дифференциатор - постоянное окно-полоска, мышиный выбор, закрепление);
- необходимость аккуратно **отфильтровать внутренние clipboard-операции самого `CyrFlip`** (главный технический риск; закрывается флагом подавления вокруг существующего `_busy`).

Если делать, то правильный путь - **маленький MVP только для текстовых данных**, с локальным файлом истории (без сети/телеметрии) и без попытки заменить системный буфер Windows.
