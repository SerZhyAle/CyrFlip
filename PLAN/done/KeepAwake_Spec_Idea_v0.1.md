## 1. Идея в одной фразе

Добавить в CyrFlip (в трее и в настройках) **два независимых переключателя**, которые на время
своей работы меняют политику простоя Windows:

1. **«Не давать компьютеру засыпать»** — система не уходит в сон/гибернацию по таймауту.
2. **«Не блокировать экран» (как при просмотре видео)** — монитор не гаснет и экран не уходит в
   блокировку по простою, ровно так, как это делает любой видеоплеер во время воспроизведения.

Оба — «на сейчас»: включил, пока идёт длинный процесс / презентация / видео; выключил — Windows
вернулась к обычным таймаутам питания.

---

## 2. Как это устроено в Windows

Одна документированная функция, без реестра и без прав администратора:

```csharp
[DllImport("kernel32.dll")]
static extern EXECUTION_STATE SetThreadExecutionState(EXECUTION_STATE esFlags);

[Flags]
enum EXECUTION_STATE : uint
{
    ES_CONTINUOUS       = 0x80000000,  // состояние держится до следующего вызова
    ES_SYSTEM_REQUIRED  = 0x00000001,  // не уходить в сон (система)
    ES_DISPLAY_REQUIRED = 0x00000002,  // не гасить монитор (режим видеоплеера)
}
```

**Два переключателя ложатся ровно на два флага** — это и делает решение чистым:

| Переключатель | Флаг |
| --- | --- |
| Не давать засыпать | `ES_SYSTEM_REQUIRED` |
| Не блокировать/гасить экран (видео) | `ES_DISPLAY_REQUIRED` |

Применяем **обобщённо, одним вызовом**, собрав маску по состоянию обоих тумблеров:

```csharp
var flags = ES_CONTINUOUS;
if (keepAwake)      flags |= ES_SYSTEM_REQUIRED;
if (keepScreenOn)   flags |= ES_DISPLAY_REQUIRED;
SetThreadExecutionState(flags);   // если оба выкл → голый ES_CONTINUOUS = сброс
```

*(Заметка: `ES_DISPLAY_REQUIRED` подразумевает и бодрствование системы — при включённом экране ОС не
уснёт. То есть «видео»-опция логически «шире». Но пользователю это два разных намерения — «пусть
качается ночью с погашенным экраном» против «пусть экран не гаснет во время просмотра» — поэтому в UI
они остаются двумя независимыми тумблерами, а внутри просто OR-им флаги.)*

Ключевые свойства механизма — от них зависит вся реализация:

- **`ES_CONTINUOUS` делает состояние «залипающим»:** достаточно **одного** вызова при каждом изменении,
  поливать в цикле не нужно. Состояние держится, пока не переустановить маску (или пока не завершится
  поток).
- **Состояние привязано к потоку.** Если поток, который его установил, завершится — Windows сбросит
  состояние. Значит вызывать надо **из долгоживущего потока** (UI-поток трея живёт всё время работы
  приложения — он подходит). Это же даёт бесплатный откат при закрытии приложения (§4).
- **Прав администратора не требуется**, системных настроек мы не меняем — только сообщаем ОС
  «я занят, не засыпай / не гаси экран». Штатный, документированный контракт (тот же, что у медиаплееров
  и презентаций).

## 3. Честная граница: что «не блокировать экран» покрывает, а что нет

Пользователь описал вторую опцию как «не блокировать экран, например как когда видео просматривают».
Именно это `ES_DISPLAY_REQUIRED` и даёт: пока флаг стоит, **монитор не гаснет**, **заставка не
стартует**, и, как следствие, **не срабатывает блокировка по простою** — то же поведение, что у
проигрывателя во время видео.

Чего этот механизм **не** отменяет (и не должен — это вне полномочий обычного приложения):

| Событие | Покрывает ли |
| --- | --- |
| Монитор гаснет по таймауту | **Да** (`ES_DISPLAY_REQUIRED`) |
| Заставка (screensaver) по простою | **Да** |
| Блокировка экрана **по простою** | **Да** — косвенно, т.к. простоя «нет» |
| Система уходит в сон по таймауту | **Да** (`ES_SYSTEM_REQUIRED`) |
| **Явная** блокировка `Win+L` | **Нет** |
| **Принудительная** блокировка по доменной политике безопасности | **Нет** |

То есть обещание в UI должно быть ровно «как при просмотре видео» — экран не гаснет и не блокируется
**по бездействию**. Ручной `Win+L` и жёсткую политику это не трогает. Формулировки:

- **Опция 1** — RU «Не давать компьютеру засыпать» / EN «Keep the computer awake» /
  UK «Не давати комп'ютеру засинати».
- **Опция 2** — RU «Не блокировать экран (как при видео)» / EN «Keep the screen on (like video)» /
  UK «Не блокувати екран (як під час відео)».
- Tooltip к опции 2: «Экран не гаснет и не блокируется по бездействию, как во время просмотра видео.
  Блокировку по паролю (Win+L или политику безопасности) это не отменяет.»

*(Более рискованный путь — реальная симуляция активности периодическим `SendInput` — в v0.1 не нужен
и не входит: `ES_DISPLAY_REQUIRED` закрывает сценарий «как видео» штатно, без ложного ввода. См. §8.)*

## 4. Откат — обязателен

Мы меняем политику простоя всей системы на время работы. Маска **должна** сбрасываться в голый
`ES_CONTINUOUS`:

- как только оба тумблера выключены (в трее или в настройках);
- при выходе из приложения (`Exit`, `Application.ApplicationExit`, `AppDomain.ProcessExit`);
- по-хорошему — и в `UnhandledException`, как уже сделано для восстановления курсора в
  `LayoutCursor.ForceRestore`.

Поскольку состояние привязано к потоку, «жёсткая» смерть процесса (TerminateProcess) очистит его
автоматически — в отличие от `SetSystemCursor`, где нужен явный аварийный откат. Явный сброс на
нормальном выходе всё равно делаем, чтобы не полагаться на это как на единственный путь.

## 5. Состояние — сохраняется между запусками (решение изменено 2026-07-28)

**Было (2026-07-25):** не запоминать; оба тумблера при каждом старте выключены. Причина —
«не спать / не гаснуть» осознанное действие на текущую сессию, а забытый поднятым тумблер грел бы
ноутбук в сумке.

**Стало (2026-07-28):** оба тумблера **сохраняются и восстанавливаются при запуске**. Причина —
галочка, которая молча забывает себя при каждом старте, читается пользователем как сломанная, а не
как задуманная; это и был исходный баг-репорт. Опасение из старого решения снято явно: подсказка в
настройках теперь прямо говорит, что забытый включённым переключатель продолжит держать компьютер
бодрым и после перезапуска и что следить за батареей CyrFlip за пользователя не станет.

Следствие для кода: два значения `KeepSystemAwake` / `KeepScreenOn` в `AppConfig` (см. §7),
`KeepAwake.Restore(system, screen)` применяет их **одним** вызовом при старте (две последовательные
установки на миг попросили бы у Windows половину политики), а сам `KeepAwake` по-прежнему ничего не
персистит — реестр пишет `CyrFlipContext`. Живой запрос всё так же снимается на выходе
(`KeepAwake.Reset()` в `Dispose` и в обработчиках выхода) — сохранённое значение это не трогает.

Проверка того, что маска действительно стала запросом Windows, — `tools/uitest/Test-KeepAwake.ps1`
(`powercfg /requests`, нужны права администратора). Изнутри процесса это неотличимо: у
`SetThreadExecutionState` нет ответа «принято», он возвращает лишь предыдущее состояние.

## 6. Пользовательский интерфейс

### 6.1 Трей

Два **отмечаемых** пункта меню (галочки) рядом с прочими тумблерами в `CyrFlipContext`:

- ☐ Не давать компьютеру засыпать
- ☐ Не блокировать экран (как при видео)

Клик по любому — переключает свой флаг и сразу пересобирает маску `SetThreadExecutionState` (§2).
Это первичная точка входа: суть в том, чтобы включать на лету, не открывая настройки.

*(Опционально: когда включён хотя бы один — менять тултип `NotifyIcon`, например
«CyrFlip — не даёт засыпать». Отдельную иконку-«чашку» в трее в v0.1 не делаем, чтобы не размывать
headline-функцию индикатора раскладки. Развилка §9.)*

### 6.2 Настройки

Те же два чекбокса на вкладке **«Общие»** в `SettingsForm`, с tooltip'ами из §3. Трей и настройки
правят одни и те же два флага и обязаны оставаться синхронными — как уже сделано для других
переключателей.

### 6.3 Локализация

Строки во все три языка UI (EN/RU/UK), как в остальном интерфейсе.

## 7. Код

Новый модуль (одна ответственность, как принято в проекте):

`src/CyrFlip/KeepAwake.cs`

```csharp
internal static class KeepAwake
{
    public static bool KeepSystemAwake { get; private set; }  // опция 1
    public static bool KeepScreenOn    { get; private set; }  // опция 2

    public static void SetSystemAwake(bool on);   // меняет флаг 1 и пересобирает маску
    public static void SetScreenOn(bool on);      // меняет флаг 2 и пересобирает маску
    public static void Restore(bool sys, bool scr); // сохранённое состояние при старте, одним вызовом
    public static void Reset();                   // голый ES_CONTINUOUS (на выходе)

    // private static void Apply(); — собирает маску из двух флагов и зовёт SetThreadExecutionState
}
```

Правки в существующих файлах:

- `WindowInterop.cs` — `SetThreadExecutionState` + enum `EXECUTION_STATE` (P/Invoke живёт здесь).
- `CyrFlipContext.cs` — два пункта-галочки; вызовы `KeepAwake.SetSystemAwake` / `SetScreenOn`;
  `KeepAwake.Reset()` на `Exit` и на `Application.ApplicationExit`; синхронизация галочек с настройками.
- `SettingsForm.cs` — два чекбокса на вкладке «Общие» + tooltip'ы.
- `AppConfig.cs` — два `REG_DWORD`: `KeepSystemAwake`, `KeepScreenOn` (по умолчанию `0`; добавлены
  2026-07-28 вместе с изменением решения §5).
- `CLAUDE.md` — упомянуть модуль в списке архитектуры и оба значения в таблице конфигурации.
- `docs/` (три языка) + `msix/store-listing-export.csv` — строка «Что нового» к следующему релизу.

Бюджет памяти и правило «хук < 1 мс» фича не задевает: один P/Invoke при переключении, вне хука.
MSIX-риска виртуализации реестра (как у LanguageHotkeys §7) здесь **нет** — реестр не трогаем.

## 8. Область v0.1 — что НЕ входит

- **Отмена явной блокировки** (`Win+L`, доменная политика) — вне полномочий приложения (§3).
- **Симуляция активности** (движение мыши/нажатия) — не нужно: `ES_DISPLAY_REQUIRED` закрывает
  сценарий «как видео» штатно и без ложного ввода.
- **Автотаймер** («держать бодрым 2 часа, потом выключить») — возможное расширение, не в v0.1.
- **Запоминание состояния между запусками** — сознательно нет (§5).
- **Отдельная иконка-индикатор «чашка» в трее** — по желанию позже (§9), чтобы не спорить с
  индикатором раскладки.

## 10. Тест-план

**Модульные (xUnit)** — логика тонкая (сборка маски из двух булей). Вынести реальный `SetThreadExecutionState`
за делегат и проверить: маска `ES_CONTINUOUS` при обоих выкл; `|ES_SYSTEM_REQUIRED` только при опции 1;
`|ES_DISPLAY_REQUIRED` только при опции 2; обе → оба бита; идемпотентность повторных Set; `Reset` даёт
голый `ES_CONTINUOUS`.

**Ручные (основное — фича про interop с питанием):**
- в Windows выставить короткие таймауты «отключать экран через 1 мин» и «сон через 2 мин»;
- опция 1 вкл, опция 2 выкл → без ввода: **система не спит**, но экран через минуту может погаснуть;
- опция 2 вкл → без ввода >1 мин: **монитор не гаснет и экран не блокируется** (сценарий «видео»);
- оба выкл → таймауты снова срабатывают (проверка сброса маски);
- закрыть CyrFlip при включённых опциях → политика питания **вернулась** (проверка §4);
- при включённой опции 2 нажать `Win+L` → экран **всё равно** блокируется (подтверждение честности §3);
- портативная и MSIX-сборки ведут себя одинаково (реестр не задействован).
