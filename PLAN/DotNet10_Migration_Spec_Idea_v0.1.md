# Спецификация-идея v0.1
## Возможный перенос CyrFlip на .NET 10

> Статус: **отложено, не планировать к реализации сейчас**.
>
> Решение от 2026-07-18: текущая версия на .NET Framework 4.8 работает, поддерживается Windows и не имеет пользовательской проблемы, которую решает сам переход. Миграция не является задачей ближайшего развития продукта.

---

## 1. Цель, если к идее вернутся

Перенести существующее WinForms-приложение с `net48` на `net10.0-windows`, не меняя его назначение и не переписывая интерфейс с нуля.

Это техническая модернизация, а не пользовательская функция. Кроссплатформенность не входит в цель: глобальный keyboard hook, Win32 clipboard, индикатор каретки и MSIX остаются Windows-специфичными.

## 2. Почему не делать сейчас

- Для пользователя не появляется новая ключевая возможность и не ожидается заметного прироста скорости.
- .NET Framework 4.8 всё ещё поддерживается как компонент Windows.
- CyrFlip маленький, а основные рисковые части уже используют Win32/COM; их нужно будет заново вручную проверять.
- Переход затронет сборку, тесты, публикацию, подпись и MSIX, поэтому отвлечёт от полезных изменений продукта.

## 3. Когда пересмотреть решение

Вернуться к оценке только при одном из условий:

1. Нужна штатная современная тёмная тема или улучшения WinForms, которые трудно/дорого реализовать на `net48`.
2. Планируется крупная новая ветка UI, где миграцию можно безопасно включить в тот же цикл тестирования.
3. Появляются проблемы поддержки/публикации, которые `net48` реально не позволяет решить.
4. Заканчивается поддержка целевой версии .NET Framework или используемых выпусков Windows.

Само появление новой версии .NET не является достаточным поводом.

## 4. Объём будущей работы

### Проект и зависимости

- изменить target framework на `net10.0-windows`;
- убрать `Microsoft.NETFramework.ReferenceAssemblies`;
- заменить `System.Web.Script.Serialization.JavaScriptSerializer` в `AppConfig` и `ClipboardHistoryService` на `System.Text.Json` с сохранением формата существующих данных;
- настроить современные ссылки на UI Automation (`System.Windows.Automation` / Windows Desktop) и проверить работу на Windows 10 и 11;
- подключить современную реализацию `ProtectedData` для DPAPI-шифрования истории;
- убрать или переоценить устаревшие атрибуты `HandleProcessCorruptedStateExceptions` в COM-коде.

### Сборка и доставка

- обновить `build.ps1`, `release.ps1`, GitHub Actions, README и MSIX-скрипт: сейчас они жёстко ссылаются на `bin/.../net48`;
- выбрать модель распространения:
  - framework-dependent: маленькая поставка, но на ПК нужен .NET 10 Desktop Runtime;
  - self-contained: Runtime включён в поставку, но размер дистрибутива больше;
- отдельно проверить MSIX, подпись, autostart и распаковку payload.

### Обязательная ручная проверка

- глобальные горячие клавиши и повторные нажатия;
- copy/restore clipboard, включая занятый буфер;
- индикатор каретки в Win32, Chromium/Electron, VS Code и браузерах;
- запуск с повышенными правами и поведение рядом с приложениями разной разрядности;
- история буфера, DPAPI-расшифровка ранее сохранённых записей;
- обычная установка, winget и MSIX/Store.

## 5. Правило реализации

Если работа будет одобрена, делать её в отдельной ветке и не смешивать с пользовательскими UI-функциями. Сначала должна появиться собирающаяся версия с тем же поведением и пройденной ручной матрицей; лишь затем допустимы улучшения, доступные в .NET 10.
