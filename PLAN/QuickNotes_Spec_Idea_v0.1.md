# Быстрые заметки (идея, v0.1)

**Статус:** черновик, не реализовано. **Дата:** 2026-08-11.
**Автор запроса:** пользователь — «создать новую спецификацию про механизм “быстрые заметки”… чаще всего это бросить какой-то код или заметку во время программирования в RAW для хранения».

---

## 1. Идея и границы

`CyrFlip` получает маленькое локальное хранилище быстрых заметок: открыть по хоткею, сразу написать или
вставить фрагмент, закрыть и продолжить работу. Это **не** редактор документов и не замена Notion. По
ощущению — Google Keep + простой Notepad, но без изображений, рисунков, облака, напоминаний и сложного
форматирования.

Главный сценарий — во время программирования сохранить в один жест:

```text
TODO: проверить race в ClipboardHistoryService
lock (_gate) { ... }
```

Текст остаётся именно текстом: без Markdown-рендера, подсветки, автоформатирования, замены табов или
«умных» кавычек. Это и есть режим **RAW**. Его ценность — фрагмент можно позднее найти, скопировать и
вставить обратно без незаметного изменения кода.

### Входит в функцию

- текстовые заметки с необязательным именем;
- чек-листы с отмечаемыми пунктами;
- создание, редактирование, удаление, копирование и поиск;
- неизменяемая дата создания и предсказуемый порядок «как создавали»;
- только локальное хранение и экспорт в открытые текстовые форматы.

### Сознательно не входит

- изображения, вложения, OCR, аудио, рисунки;
- rich text, HTML, таблицы, ссылки с превью, Markdown-preview и подсветка синтаксиса;
- теги, напоминания, совместное редактирование, аккаунт и облачная синхронизация;
- автоматическое превращение каждого элемента clipboard history в заметку.

Последний пункт важен: история буфера — шумный кратковременный поток, а заметка — намеренно сохранённая
информация. Между ними должна быть явная команда пользователя.

## 3. UX и поведение

### 3.1. Точки входа

1. Пункт в tray-меню: **«Быстрые заметки»** — открывает список и возвращает к уже открытому окну.
2. Глобальный хоткей **`Ctrl+Alt+N`** по умолчанию — сразу создаёт новую заметку и ставит курсор в поле
   текста. Комбинация настраивается и проверяется на конфликт со всеми другими хоткеями CyrFlip.
3. Пункт текстового контекстного меню CyrFlip: **«Сохранить выделение в быстрые заметки»**. Он берёт
   только выделенный plain text; пользователь всё равно должен подтвердить сохранение закрытием/`Ctrl+S`.
4. Кнопка `+` в окне заметок — создание пустой заметки.

Новая заметка открывается без обязательного диалога «назовите файл». Если имя не нужно, пользователь
начинает печатать сразу.

### 3.2. Окно заметок

Окно состоит из узкой левой колонки и правого редактора.

| Область | Содержимое и правило |
| --- | --- |
| Шапка | `+`, строка поиска, счётчик найденных заметок, кнопка настроек. |
| Список слева | По одному элементу: значок текста/списка, имя или первая непустая строка текста, дата создания, короткий preview. Для реально безымянной заметки не сохраняется искусственный заголовок. |
| Редактор справа | Необязательное поле «Имя» и ниже RAW-текст **либо** редактор списка. Переключение типа доступно, пока преобразование не теряет данных; иначе — с явным предупреждением. |
| Низ окна | Дата создания, дата последнего изменения, «Копировать», «Экспорт», «Удалить». |

Окно запоминает размер и положение. При исчезнувшем мониторе оно появляется в рабочей области основного
экрана. `Esc` сначала снимает фокус с поиска/редактора, затем скрывает окно; приложение из трея не
завершается.

### 3.3. Безымянные заметки

`Title` может быть `null`. Пустая строка или строка из пробелов при сохранении считается отсутствующим
именем, а не заголовком `«Без имени»`.

Для списка выводится производное представление: первая непустая строка текста или первый пункт списка,
обрезанный для превью. Это только UI и **не записывается** в `Title`, поэтому последующее изменение
первой строки не портит модель и поиск.

Совсем пустая новая заметка при закрытии не создаётся. Если в заметке уже есть текст, пункты или имя,
она сохраняется даже при пустом теле.

### 3.4. RAW-текст и списки

**Текстовая заметка** — последовательность символов как введена пользователем. Сохраняются переводы
строк и табы; текст не нормализуется. Внешний вид редактора — моноширинный шрифт, перенос длинных строк
настраиваемый, по умолчанию выключен для комфортного просмотра кода.

**Заметка-список** — массив пунктов `{ text, checked }`. Пункты можно добавлять, удалять, менять местами
и отмечать. В MVP — один уровень, без подзадач. Преобразование «текст → список» делит текст на строки;
обратное преобразование отдаёт по одной строке на пункт, с префиксом `- [ ]` / `- [x]` только в момент
явного экспорта, а не в RAW-поле.

`Ctrl+S` немедленно сохраняет. Также работает debounce-автосохранение через 750 мс после последнего
изменения, а при закрытии/смене заметки — немедленное сохранение. Не должно быть модального вопроса
«сохранить изменения?» в момент, когда пользователю нужно вернуться к коду.

### 3.5. Порядок и даты

Каждой заметке при первом успешном сохранении назначается `CreatedAtUtc`; оно никогда не меняется.
`UpdatedAtUtc` меняется при содержательном редактировании, переключении флажка или имени, но не влияет
на стандартный список.

- основной порядок: **сначала новые**, `CreatedAtUtc DESC`;
- равные отметки времени: стабильный tie-breaker `Id DESC`, чтобы порядок был детерминирован;
- отдельные режимы сортировки «сначала старые» и «недавно изменённые» допустимы позднее, но не заменяют
  стандарт «как создавали»;
- создание из выделения получает дату на момент подтверждённого создания, а не на момент копирования.

## 4. Поиск

Поиск — центральная функция, потому что заметки часто сохраняются без имени.

- Строка поиска ищет подстроку одновременно в `Title`, RAW-тексте и тексте пунктов списка.
- По умолчанию поиск case-insensitive и Unicode-safe, но не меняет сохранённый текст. `HttpClient` найдёт
  `httpclient`; поиск с учётом регистра — возможный этап 2 для кода и идентификаторов.
- Поиск стартует с первого символа, без минимальной длины запроса, результат обновляется с debounce
  150 мс. Пустой запрос показывает всё в порядке создания.
- Совпадение отображается в preview; при открытии заметки выполняется переход к первому совпадению.
- Найденные заметки сохраняют общий порядок по `CreatedAtUtc DESC`, а не получают неочевидный рейтинг.
- Поиск работает только по локальному хранилищу и не использует Windows Search, сеть или телеметрию.

В MVP допустим линейный поиск по заметкам, загруженным в память: типичный набор коротких заметок мал, а
простота важнее внешней базы/индекса. Перед выпуском нужно замерить 10 000 заметок по 10 КБ: ввод в
поиске не должен блокировать UI дольше 100 мс. Если не проходит — построить локальный префиксный/триграммный
индекс в памяти, не меняя пользовательский формат хранения.

## 5. Данные, локальность и приватность

### 5.1. Модель

```csharp
QuickNote
{
    Guid Id;
    DateTime CreatedAtUtc;    // порядок создания, неизменяемо
    DateTime UpdatedAtUtc;
    string? Title;            // null = заметка без имени
    QuickNoteKind Kind;       // Text или Checklist
    string RawText;           // только для Text, без преобразования
    List<QuickNoteItem> Items;// только для Checklist
}

QuickNoteItem { Guid Id; string Text; bool IsChecked; int Position; }
```

У записи нет поля «автоматический заголовок», HTML, RTF или ссылки на медиа. Максимальный размер одной
заметки в MVP — 512 КБ UTF-8; при превышении импорт/вставка отклоняется понятным сообщением, а уже
сохранённые данные не теряются.

### 5.2. Хранение

Нужна отдельная от clipboard history сущность:

- расположение: MSIX-aware локальная папка CyrFlip рядом с `layout.txt` и существующим
  `clipboard-history.log`;
- файл `quick-notes.log`: append-only журнал операций, каждая строка содержит DPAPI-зашифрованный
  (`CurrentUser`) снимок операции/заметки;
- операции: `create`, `update`, `delete`; при старте журнал проигрывается в память;
- после 500 операций или при выходе выполняется безопасная компакция в актуальный снимок: временный файл,
  flush, атомарная замена и резервная `.bak`;
- повреждённая строка пропускается и фиксируется только в диагностическом логе; приложение не должно
  потерять все остальные заметки или упасть.

Это намеренно не SQLite: проект остаётся на `net48`, без нового runtime/NuGet-зависимости, а для
небольшого персонального блокнота append-only журнал легко отлаживать и безопасно восстанавливать.

### 5.3. Приватность

В заметках могут оказаться ключи, токены и внутренний код. Поэтому:

- всё хранится только локально и зашифровано DPAPI пользователя Windows;
- функция выключена по умолчанию и объясняет это при первом включении;
- нет сети, аналитики, индексирования Windows Search или фоновой отправки данных;
- «Удалить заметку» сначала спрашивает подтверждение и затем удаляет её из памяти и следующей
  компакции; undo в MVP отсутствует;
- «Удалить все быстрые заметки» требует отдельного подтверждения и уничтожает журнал и `.bak`;
- экспорт всегда явный: перед записью незашифрованного файла показать путь и предупреждение, что файл
  уже не защищён DPAPI.

Постоянное хранение кода — не хранилище секретов. В UX нужна короткая честная подсказка: не сохранять
пароли, production-токены и приватные ключи.

## 6. Экспорт и Google Keep

### 6.1. Универсальный экспорт

MVP предоставляет для одной заметки `Copy` и `Export as .txt`; для всех заметок — `Export as Markdown`.
Это не влияет на RAW-оригинал:

- текстовая заметка: имя (если есть), затем точный текст;
- список: имя (если есть), затем строки `- [ ]` и `- [x]`;
- даты в экспорт по умолчанию не добавляются, чтобы код можно было сразу вставить обратно; они доступны
  в опции «добавить метаданные».

### 6.2. Что реально возможно с Google Keep

У Google есть REST API `notes.create`, поддерживающий текстовые и list-заметки, однако официальная
документация описывает его как API для **enterprise-администраторов Google Workspace**. Оно требует
настройки OAuth/domain-wide delegation и разрешений администратора; это не универсальный, безнастроечный
экспорт в личный Google-аккаунт. [Обзор Google Keep API](https://developers.google.com/workspace/keep/api/guides),
[метод создания заметки](https://developers.google.com/workspace/keep/api/reference/rest/v1/notes/create).

Поэтому в MVP кнопка **«Копировать для Google Keep»**:

1. формирует plain text или checklist-строки из заметки;
2. кладёт их в системный clipboard;
3. по желанию открывает `https://keep.google.com/`;
4. показывает короткое сообщение «Создайте заметку в Keep и вставьте текст».

Это честный перенос, который работает для личного аккаунта и не требует передавать CyrFlip пароль,
cookie или токен. Не использовать неофициальное управление браузером, web-scraping, reverse engineering
приватных Keep-endpoint'ов и автоматический импорт Takeout-архивов: это хрупко и рискованно для данных.

**Этап 3, только при отдельном решении:** «Export to Google Keep (Workspace)» через официальный API.
Предпосылки — тестовый Workspace-домен, письменное понимание нужных scopes/администраторского согласия,
OAuth-экран, отзыв токена и негативные тесты прав доступа. Эта возможность не должна показываться
обычным пользователям, пока её применимость не подтверждена на реальном tenant.

Google Keep умеет экспортировать собственные заметки через Google Takeout, включая текст и элементы
списка, но это путь **из** Keep, а не документированный импорт в него. [Справка Google о Takeout](https://support.google.com/keep/answer/10017039?hl=en).

## 7. Архитектура в CyrFlip

Функция опирается на уже существующий tray-first WinForms-каркас, `Win32Clipboard`, `ClipboardHandler`,
`ForegroundActivator` и MSIX-aware локальные пути, но не разделяет с `ClipboardHistoryService` его данные
или включение.

Предлагаемые компоненты:

- `QuickNote.cs`, `QuickNoteItem.cs` — чистая модель и инварианты дат/RAW-содержимого;
- `QuickNotesStore.cs` — DPAPI-журнал, replay, компакция, резервная копия и атомарная запись;
- `QuickNotesService.cs` — память, CRUD, сортировка, debounce сохранения и поиск;
- `QuickNotesWindow.cs` — список, поиск и редактор заметки;
- `QuickNotesCapture.cs` — безопасный путь «выделение → новый черновик», использующий существующий
  copy/restore pipeline и не оставляющий техническую копию в истории буфера;
- изменения в `AppConfig.cs` — enabled, hotkey, геометрия окна, выбранная заметка/режим переноса строк;
- изменения в `CyrFlipContext.cs`, `KeyboardHook.cs`, `SettingsForm.cs`, локализации и tray-меню.

Контракт ответственности:

```text
горячая клавиша / tray / контекстное меню
                  ↓
          CyrFlipContext
                  ↓
 QuickNotesService ───── QuickNotesStore (DPAPI на диске)
        ↓
 QuickNotesWindow  ←→  Win32Clipboard (только Copy/Export/capture)
```

UI не читает и не пишет файлы напрямую. Store не знает о WinForms. Логику сортировки и поиска надо вынести
в тестируемые классы без окон, registry и DPAPI — по тому же принципу, что `ClipboardHistoryOrder`.

## 8. MVP, этапы и критерии готовности

### MVP

1. Тумблер функции, tray-пункт, настраиваемый hotkey `Ctrl+Alt+N` и единая локализация EN/RU/UK.
2. Создание/редактирование/удаление текстовых заметок с необязательным именем.
3. RAW-поведение: точное сохранение табов, переносов строк и символов; моноширинный редактор; перенос
   строк по умолчанию выключен.
4. Чек-листы одного уровня с сохранением флажков и порядка пунктов.
5. Неизменяемая дата создания, список «сначала новые», дата изменения только как метаданные.
6. Поиск по имени, тексту и пунктам списка.
7. Локальный DPAPI append-only журнал, обработка повреждённой записи, компакция и `.bak`.
8. Copy, экспорт `.txt`/Markdown и ручной перенос в Google Keep через clipboard; без сетевого API.
9. Создание заметки из выделенного текста без загрязнения clipboard history техническими операциями.
10. Юнит-тесты модели, порядка, поиска, преобразования списка и replay/compaction хранилища; smoke-test
    ручного создания/поиска/перезапуска на обычной и MSIX-сборке.

### Этап 2

- сортировка «старые сначала» / «недавно изменённые»;
- поиск с учётом регистра и поиск только в текущем типе заметок;
- горячая клавиша «сохранить текущее выделение без открытия редактора» с коротким toast;
- режим «всегда поверх» и компактное окно только со списком;
- безопасный экспорт всех заметок в один зашифрованный backup и явный импорт этого backup;
- более строгая оптимизация поиска после замера на 10 000 заметок.

### Этап 3

- Workspace-only экспорт в Google Keep после отдельного решения и проверки tenant;
- теги/закрепление — только если реальное использование покажет необходимость; они не входят в исходный
  «быстро бросить RAW-фрагмент» сценарий.

### Acceptance criteria

- Пользователь может за ≤2 действия после hotkey начать писать и сохранить без обязательного имени.
- Вставленный код после перезапуска посимвольно совпадает с исходником, включая CRLF/LF и табы.
- Изменение существующей заметки не меняет её место в стандартном порядке списка.
- Фрагмент находится по части тела, даже если у заметки нет имени.
- После остановки приложения и запуска все сохранённые заметки и флажки восстановлены.
- При порче одной записи журнала доступны остальные корректные записи.
- Никакое действие заметок не делает сетевого запроса; «Google Keep» в MVP только копирует текст и при
  согласии открывает браузер.

## 9. Риски и решения

| Риск | Решение |
| --- | --- |
| Заметки становятся вторым непонятным clipboard manager | Явное создание только по команде; отдельные данные и отдельная настройка. |
| «RAW» портится редактором | Нет форматтера/Markdown; тесты на точность CRLF, LF, табов, Unicode и длинных строк. |
| Утечка кода или токена | DPAPI, отсутствие сети, явный экспорт и предупреждение; не обещать хранение секретов. |
| Бесконечный журнал замедляет запуск | Компакция и замер на 10 000 заметок; store изолирован для дальнейшей замены реализации. |
| Пользователь ждёт бесшовный Keep sync | В интерфейсе называть MVP «Копировать для Google Keep», не «Синхронизировать» или «Экспортировать напрямую». |
| Прямой API не подходит личному аккаунту | Не делать его частью MVP; рассматривать только enterprise Workspace-путь. |

## 10. Итог

Функция хорошо соответствует CyrFlip, если сохранить её маленькой и намеренной: **быстро зафиксировать
текст или код, потом найти и вернуть без искажений**. Самые важные решения уже заданы этой
спецификацией: имя необязательно, стандартный порядок определяется временем создания, поиск смотрит в
содержимое, а код хранится как RAW.

Google Keep стоит поддержать практичным ручным переносом через clipboard, но не обещать личным аккаунтам
несуществующую бесшовную синхронизацию. Это сохраняет главные свойства CyrFlip — локальность, простоту и
отсутствие лишних зависимостей.
