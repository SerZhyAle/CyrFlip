# Спецификация-идея v0.1
## Открытый обмен историей буфера и быстрыми заметками

> Статус: идея / product-spec, не утверждённая к реализации.
>
> Связана с [ClipboardHistoryTray_Spec_Idea_v0.1.md](done/ClipboardHistoryTray_Spec_Idea_v0.1.md) и [QuickNotes_Spec_Idea_v0.1.md](QuickNotes_Spec_Idea_v0.1.md). Эта спецификация определяет **переносимый файл обмена**, а не внутреннее хранилище приложения.

---

## 1. Цель

Дать пользователю простой способ перенести между ПК и устройствами два вида текстовых данных CyrFlip:

- историю буфера обмена;
- быстрые заметки.

Экспорт создаёт один обычный текстовый файл. Его можно:

- открыть в Блокноте, VS Code или любом другом текстовом редакторе;
- прочитать на телефоне как заметку;
- передать вручную через мессенджер, облако, кабель или флешку;
- позже импортировать обратно в CyrFlip.

Это **не** облачная синхронизация и не механизм совместного редактирования. CyrFlip не отправляет файл в сеть и не следит за папками автоматически.

---

## 2. Главный принцип приватности

Файл обмена всегда открыт:

- без шифрования;
- без пароля;
- без DPAPI;
- без скрытого или закодированного содержимого.

Поэтому он намеренно удобен для чтения, но может содержать пароли, личные сообщения и фрагменты документов. Перед экспортом приложение показывает предупреждение:

> «Файл будет обычным незашифрованным текстом. Не передавайте его через небезопасные каналы и удалите после переноса, если он больше не нужен.»

Пользователь может отменить экспорт. Предупреждение показывается при каждом экспорте истории буфера; для экспорта только заметок его можно отключить настройкой «Больше не предупреждать для заметок».

Открытый файл не отменяет защиты локальной истории: рабочее постоянное хранилище clipboard history по-прежнему может оставаться DPAPI-защищённым, как описано в базовой спецификации. Расшифровка нужна только на момент явного экспорта, выбранного пользователем.

---

## 3. Пользовательские сценарии

### 3.1 Забрать текст на телефон

Пользователь выделяет несколько записей истории и две быстрые заметки, выбирает `Экспортировать…`, сохраняет `CyrFlip-2026-08-11.txt` в папку облака и открывает его на телефоне. В файле сразу видны заголовки и сам текст, без установки CyrFlip.

### 3.2 Перенести рабочие заготовки на другой ПК

Пользователь экспортирует заметки и закреплённые элементы истории на первом ПК, передаёт один файл, затем выбирает `Импортировать…` на втором. CyrFlip показывает, сколько заметок и записей будет добавлено, а одинаковые данные не дублирует.

### 3.3 Использовать файл как временную текстовую заметку

Файл можно открыть и вручную прочитать или дополнить. При последующем импорте CyrFlip принимает только корректно размеченные элементы, а обычный текст вне элементов оставляет без изменений и игнорирует. Поэтому файл не превращается в хрупкий внутренний формат.

## 4. Состав данных

### 4.1 Быстрые заметки

Быстрая заметка — самостоятельный объект, не зависящий от времени жизни записи истории. Её модель повторяет [спецификацию быстрых заметок](QuickNotes_Spec_Idea_v0.1.md):

- постоянный `id` (UUID);
- необязательный заголовок;
- тип `text` или `checklist`;
- RAW-текст либо пункты списка с состоянием флажков;
- неизменяемое время создания и время последнего изменения (`UTC`).

Заметка подходит для шаблонов ответов, адресов, команд, часто используемых фрагментов и личных пометок. RAW-текст экспортируется без нормализации: табы, пустые строки и переводы строк остаются частью данных. Редактирование и UI списка заметок — отдельная задача; эта спецификация описывает только их перенос.

### 4.2 Запись истории буфера

В обменный файл попадает снимок текстовой записи:

- `id` — хеш нормализованного текста из истории;
- время последнего копирования (`copied-at`, UTC);
- признак закрепления;
- полный plain text;
- при наличии — имя приложения-источника и заголовок окна.

В MVP переносится только plain text. RTF, изображения, HTML и прочие двоичные clipboard-форматы не экспортируются. Если в будущей версии RTF появится во внутренней истории, экспорт по-прежнему передаёт её читаемую текстовую форму; рядом выводится пометка, что форматирование не переносится.

## 5. Файл CyrFlip Exchange Text v1

### 5.1 Имя, расширение и кодировка

- рекомендованное имя: `CyrFlip-YYYY-MM-DD.txt`;
- фильтр диалога: `CyrFlip Exchange (*.cyrflip.txt;*.txt)`;
- кодировка: `UTF-8` без BOM;
- переводы строк при записи: `LF`; при импорте принимаются `LF` и `CRLF`;
- файл — текст, не архив и не база данных.

Расширение `.txt` важно: оно открывается на Windows, Android, iOS и в почтовых/облачных просмотровщиках без специального приложения. Дополнительное `.cyrflip` в имени лишь помогает человеку понять происхождение файла и не является обязательным.

### 5.2 Каркас

Первая непустая строка должна быть маркером формата:

```text
# CyrFlip Exchange Text v1
```

Затем идёт короткая шапка для человека и импортёра:

```text
Exported-At: 2026-08-11T14:23:11Z
Application: CyrFlip
Includes: quick-notes, clipboard-history

# Quick notes
...

# Clipboard history
...
```

Поля шапки имеют вид `Name: value`, порядок не важен. Неизвестные поля и разделы импортёр пропускает. `Exported-At` служит только справкой; он не влияет на объединение данных.

### 5.3 Один элемент

Элементы хранятся в Markdown-подобных блоках. Их метаданные остаются короткими и читаемыми, а полезная нагрузка — исходным многострочным текстом в fenced-блоке.

````text
## Note
Id: 7c2f0d04-0c09-4e11-af08-d61bb0748ab9
Title: Ответ клиенту
Kind: text
Created-At: 2026-08-09T10:30:00Z
Updated-At: 2026-08-11T14:18:03Z

```text
Здравствуйте!
Спасибо за обращение. Вернёмся с ответом до пятницы.
```
````

````text
## Clipboard
Id: sha256:9d4e1e239d4e1e239d4e1e239d4e1e239d4e1e239d4e1e239d4e1e239d4e1e23
Copied-At: 2026-08-11T14:21:45Z
Pinned: false
Source-Application: notepad.exe
Source-Window: Черновик — Блокнот

```text
Текст, который был в буфере обмена.
```
````

Пустой текст допустим. Заголовок заметки может быть пустым; тогда CyrFlip при показе использует первую непустую строку текста, первый пункт списка или `Без названия`. Для `Kind: checklist` тело содержит обычные строки `- [ ] текст` и `- [x] текст`: они сразу читаются человеком и восстанавливают отметки при импорте.

### 5.4 Границы текста

Для содержимого применяется Markdown-правило переменной длины ограждения:

- экспортёр выбирает строку из обратных кавычек (`) длиннее любой последовательности обратных кавычек в самом тексте;
- первая строка ограждения имеет вид ```` ```text ```` (или с большим числом кавычек);
- закрывающая строка состоит из того же числа кавычек;
- всё между ними — исходный текст без экранирования и без изменения пробелов.

Так в файл можно безопасно записать и фрагмент Markdown, и исходный код с обычным ````` ``` ````` внутри. Если текст содержит слишком длинные последовательности кавычек, экспортёр просто выбирает ещё более длинное ограждение.

Строки метаданных не предназначены для ручной передачи тела записи: переводы строк в `Title` и полях источника заменяются пробелом. Двоеточие в значении допустимо — отделяет поле только первое двоеточие.

### 5.5 Пример полного файла

````text
# CyrFlip Exchange Text v1
Exported-At: 2026-08-11T14:23:11Z
Application: CyrFlip
Includes: quick-notes, clipboard-history

# Quick notes

## Note
Id: 7c2f0d04-0c09-4e11-af08-d61bb0748ab9
Title: Ответ клиенту
Kind: text
Created-At: 2026-08-09T10:30:00Z
Updated-At: 2026-08-11T14:18:03Z

```text
Здравствуйте!
Спасибо за обращение.
```

# Clipboard history

## Clipboard
Id: sha256:9d4e1e239d4e1e239d4e1e239d4e1e239d4e1e239d4e1e239d4e1e239d4e1e23
Copied-At: 2026-08-11T14:21:45Z
Pinned: false
Source-Application: notepad.exe

```text
Текст из буфера.
```
````

## 6. Экспорт

### 6.1 Точка входа и выбор данных

В окне истории и окне быстрых заметок есть пункт `Экспортировать…`; общий пункт также доступен в разделе настроек «Данные». Диалог предлагает флажки:

- `Быстрые заметки` — включено по умолчанию;
- `Закреплённые элементы истории` — включено по умолчанию;
- `Остальная история буфера` — выключено по умолчанию.

Если включена остальная история, пользователь выбирает объём: `последние 50`, `последние 100`, `за последние 7 дней` или `вся история`. Выбор по умолчанию специально консервативен: не надо случайно выгружать весь рабочий clipboard за годы.

Записи экспортируются в порядке, удобном для чтения: заметки — от новых к старым по `Created-At` (как в их основном списке); история — закреплённые первыми, затем по `Copied-At` от новых к старым. Универсальный файл дополняет, а не отменяет предусмотренный у заметок экспорт одной заметки в `.txt` и всех заметок в Markdown.

### 6.2 Надёжная запись

Экспортёр формирует файл целиком во временном файле в выбранной папке, закрывает его, затем атомарно переименовывает в итоговое имя. При ошибке исходный файл не перезаписывается. Если имя уже существует, стандартный Save dialog просит подтвердить замену.

После успеха CyrFlip показывает число экспортированных заметок и записей. Он не открывает папку и не отправляет файл куда-либо сам.

## 7. Импорт и объединение

### 7.1 Предпросмотр перед изменением данных

Пункт `Импортировать…` открывает только выбранный пользователем `.txt`/`.cyrflip.txt`. До записи CyrFlip разбирает файл и показывает результат:

- найдено заметок и записей истории;
- сколько будет добавлено;
- сколько уже есть и будет пропущено;
- сколько конфликтующих заметок будет обновлено;
- сколько блоков не удалось прочитать.

При нуле корректных блоков импорт не запускается. Причина отображается простым текстом, например: «Не найден маркер `# CyrFlip Exchange Text v1`».

### 7.2 Правила merge

Импорт по умолчанию только добавляет или обновляет данные; он ничего не удаляет из текущей истории и заметок.

| Вид | Совпадение | Результат |
| --- | --- | --- |
| Заметка | одинаковый `Id` | более новая по `Updated-At` заменяет поля, RAW-текст или пункты списка; одинаковое время — текущая локальная версия остаётся |
| Заметка | тот же заголовок/текст, но другой `Id` | это две разные заметки, обе сохраняются |
| История | одинаковый `Id` (SHA-256 текста) | не создаётся дубль; более новый `Copied-At` поднимает существующую запись и обновляет доступные метаданные |
| История | другой `Id` | добавляется новой записью |

`Pinned: true` побеждает `false` при объединении: импорт закреплённой записи не должен случайно снять локальное закрепление. В файле не предусматривается операция удаления или «заменить всё» — перенос остаётся безопасным и предсказуемым.

### 7.3 Ручные правки файла

Человек может отредактировать текст и затем импортировать его. Правила:

- импортируются только полные блоки `## Note` и `## Clipboard` с корректным `Id`, временем и закрытым текстовым ограждением;
- неизвестные поля, заголовки и свободный текст игнорируются;
- повреждённый блок пропускается, остальные продолжают импортироваться;
- текст хранится как есть, включая Unicode, пустые строки и пробелы внутри fenced-блока;
- `Id` clipboard-записи повторно проверяется по содержимому. При несовпадении хеша CyrFlip не импортирует этот блок и объясняет это в отчёте;
- у вручную созданной заметки без UUID CyrFlip предлагает «Импортировать как новую заметку» и генерирует UUID только после подтверждения.

Последнее правило даёт удобный путь: пользователь может написать на телефоне новый блок `## Note` без `Id`, а CyrFlip превратит его в заметку, не ослабляя проверку существующих данных.

### 7.4 Ограничения и защита от плохого файла

Импорт читает файл потоково и ограничивает:

- размер одного файла — 25 MB;
- размер одной clipboard-записи — 128 KB текста (такой же предел, как у истории);
- размер одной заметки — 512 KB UTF-8 (как в спецификации быстрых заметок);
- количество импортируемых объектов за одну операцию — 10 000;
- длину метаданных и заголовка заметки — 4 KB.

Нарушения не приводят к падению приложения: элемент пропускается с причиной. Перед обработкой CyrFlip не исполняет содержимое, не открывает ссылки и не интерпретирует текст как команды.

## 8. Архитектура

Возможные новые компоненты:

- `CyrFlipExchangeWriter.cs` — выбирает данные, создаёт открытый UTF-8-файл и записывает его атомарно;
- `CyrFlipExchangeReader.cs` — потоково читает v1, возвращает валидные блоки и предупреждения;
- `CyrFlipExchangeModels.cs` — DTO формата (`ExchangeNote`, `ExchangeClipboardItem`, отчёт импорта);
- `QuickNotesService.cs` — хранение и merge быстрых заметок;
- дополнения `ClipboardHistoryService.cs` — выборка снимка истории и merge импортированных текстовых записей;
- дополнения в `SettingsForm` / окнах истории и заметок — диалоги выбора, предупреждение и preview импорта.

Парсер и writer не должны зависеть от WinForms, чтобы их можно было покрыть unit-тестами. Внутренние форматы хранения (`clipboard-history.log`, будущая база заметок) не являются форматом обмена и могут меняться независимо от v1.

## 9. MVP и проверка

### MVP

1. Использование модели быстрых заметок: необязательный заголовок, RAW-текст или checklist, UUID и даты.
2. Экспорт заметок и plain-text истории в один `.txt` UTF-8-файл по формату v1.
3. Диалог с выбором данных и обязательным предупреждением при включённой истории.
4. Предпросмотр импорта и безопасный merge без удаления локальных данных.
5. Поддержка ручного чтения и редактирования файла по правилам §7.3.
6. Ограничения размера и отчёт о пропущенных записях.

### Тесты

- round-trip заметки и истории, в том числе кириллица, emoji, пустые строки, текст с Markdown и последовательностями обратных кавычек;
- файлы с `LF` и `CRLF`;
- повторный импорт не создаёт дублей;
- конфликт заметки выбирает более новый `Updated-At`;
- несовпадающий hash clipboard-текста отклоняется;
- повреждённый блок не мешает импортировать последующие;
- файл больше лимита, незакрытое ограждение и неизвестная версия показывают понятную ошибку;
- экспорт нельзя получить в зашифрованном, base64 или ином нечитаемом виде.

---

## 10. Не входит в задачу

- автоматическая синхронизация с облаком, телефоном или папкой;
- сетевой обмен и учётная запись;
- шифрование или пароль экспортного файла;
- экспорт изображений, файлов, RTF/HTML с форматированием;
- удаление локальных данных по содержимому импортируемого файла;
- редактирование файлов «на месте» приложением.

---

## 11. Итог

Файл v1 — это сознательно простой, переносимый и человекочитаемый снимок. Он не конкурирует с защищённым внутренним хранением: пользователь сам в явном действии решает выгрузить нужные данные в обычный текст, чтобы прочитать их где угодно и при необходимости вернуть в CyrFlip.
